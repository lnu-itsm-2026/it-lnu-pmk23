# Runbook: Мережа лабораторії IoT (REQ #55)

| Поле | Значення |
|---|---|
| Сервіс | Мережа (`service:02`) |
| Пов'язаний запит | REQ #55 |
| Пов'язані зміни | RFC «VLAN 50 для IoT-лабораторії» (коментар у #55); RFC «Wi-Fi-сегмент для IoT» (коментар у #55) |

## 1. Призначення

Окрема ізольована мережа для лабораторії інтернету речей кафедри: 30 пристроїв, з них 15 підключені кабелем і 15 через Wi-Fi. Мета: щоб пристрої мали лише необхідний доступ і не створювали ризику для внутрішньої мережі університету.

## 2. Архітектура

- VLAN: `50`, комутатор корпусу 3 (`SW-K3-01`).
- Підмережа: `10.50.0.0/24`, шлюз: `10.50.0.1`.
- DHCP: сервер на `FW-CORE-01`, динамічний діапазон `10.50.0.100–10.50.0.200`, адреси `10.50.0.10–10.50.0.99` для резервування під відомі пристрої.
- Дротові пристрої: порти `Gi1/0/10–Gi1/0/24` на `SW-K3-01`, access-порти у VLAN 50.
- Wi-Fi: SSID `IoT-Lab-Sensors`, прив'язаний до VLAN 50, діапазон 2,4 ГГц, автентифікація WPA2-PSK, точки доступу `AP-K3-01` та `AP-K3-02`, контролер `WLC-01`.
- Схема: `docs/diagrams/iot-lab-network.png`.

## 3. Правила доступу

| Звідки | Куди | Дозволено | Примітка |
|---|---|---|---|
| IoT VLAN (10.50.0.0/24) | Інтернет | Так (TCP 80/443, UDP 53/123) | Лише вихідні з'єднання |
| IoT VLAN | Внутрішні мережі університету | Ні | Повна ізоляція |
| IoT VLAN | Керування мережевим обладнанням | Ні | |
| Пристрої між собою (Wi-Fi) | | Ні | Client isolation на `WLC-01` |
| Ззовні | IoT VLAN | Ні | Без вхідних з'єднань |
| Будь-яке інше джерело | IoT VLAN | Ні | Виключення лише через погоджений RFC |

## 4. Особливості пристроїв

- Паролі на частині пристроїв змінити не можна, тому такі пристрої вважаються недовіреними.
- Датчики з Wi-Fi підключаються лише до SSID `IoT-Lab-Sensors` і не мають доступу до внутрішніх ресурсів.
- Реєстр пристроїв: `runbooks/iot-lab-devices.csv` (назва, MAC, тип підключення, власник).

## 5. Процедури

### 5.1 Підключення нового дротового пристрою
1. Отримати від кафедри дані пристрою: назва, модель, MAC.
2. Внести в реєстр `runbooks/iot-lab-devices.csv`.
3. Призначити вільний порт із `Gi1/0/10–Gi1/0/24` на `SW-K3-01` у VLAN 50.
4. Створити резервування DHCP із діапазону `10.50.0.10–10.50.0.99`.
5. Перевірити отримання IP та доступ до інтернету.
6. Перевірити, що доступ до внутрішніх підмереж заблокований.
7. Повідомити заявника.

### 5.2 Підключення нового Wi-Fi-пристрою
1. Отримати модель, MAC, підтримувані стандарти Wi-Fi (2,4 ГГц, WPA2).
2. Внести в реєстр `runbooks/iot-lab-devices.csv`.
3. Додати MAC у білий список на `WLC-01` і створити резервування DHCP.
4. Підключити пристрій до SSID `IoT-Lab-Sensors`.
5. Перевірити IP, інтернет, ізоляцію.
6. Повідомити заявника.

### 5.3 Перевірка після змін
- `show ip dhcp binding` на `FW-CORE-01`: пристрій отримує адресу з `10.50.0.0/24`.
- Ping `8.8.8.8` та відкриття веб-сторінки з пристрою: працює.
- Ping `10.0.0.1` (внутрішня мережа) із VLAN 50: недоступно.
- Wi-Fi-пристрої між собою: не бачать один одного.

## 6. Відкат

- Wi-Fi: вимкнути SSID `IoT-Lab-Sensors` на `WLC-01`.
- VLAN: від'єднати порти `Gi1/0/10–Gi1/0/24` від VLAN 50 і видалити VLAN 50 на `SW-K3-01`; повернути порти до попереднього стану із резервної конфігурації `SW-K3-01_2026-11-15.cfg`.
- Після відкату перевірити, що інші мережі працюють без змін, і повідомити заявника.

## 7. Моніторинг і діагностика

- Що перевіряємо: доступність SSID `IoT-Lab-Sensors`, кількість клієнтів на `WLC-01`, DHCP-оренди на `FW-CORE-01`, журнали `SW-K3-01`.
- Типові проблеми:
  - Пристрій не отримує IP: перевірити VLAN 50 на порту / SSID і DHCP-діапазон `10.50.0.100–10.50.0.200`.
  - Wi-Fi-датчик не підключається: перевірити діапазон (2,4 ГГц), WPA2-PSK, MAC у білому списку.
  - Немає інтернету: перевірити правила на `FW-CORE-01`.

## 8. Ризики та заходи

| Ризик | Захід |
|---|---|
| Компрометація датчика з незмінним паролем | Ізоляція VLAN, client isolation, обмеження вихідного доступу |
| Рух до внутрішньої мережі | Заборона доступу до внутрішніх підмереж |
| Зайві пристрої в мережі | Реєстр пристроїв, білий список MAC, резервування DHCP |
| Нерозпізнані зміни | Усі зміни лише через RFC |

## 9. Критерії завершення запиту

- Кафедра підтвердила, що отримала реквізити підключення.
- Дротові (15) та Wi-Fi (15) пристрої підключені й перевірені.
- Runbook оновлено.
- Тікет закривається лише після підтвердження від користувача, а не після самої відправки листа.
