# Постмортем: Збій комутатора в гуртожитку №3 (INC #54) — 2026-10-22

| | |
|---|---|
| Сервіс | Мережа (Wi-Fi) |
| Пріоритет | P2 (High) |
| Тривалість | з ~22:00 вчора до 19:00 сьогодні |
| Кого зачепило | мешканці 4-го поверху гуртожитку №3 |
| Виявлено | скаргою користувача через форму на сайті |

Збій у роботі Wi-Fi на одному з поверхів гуртожитку через зависання мережевого обладнання, що призвело до тривалої відсутності підключення в студентів.

## Таймлайн

| Час | Що сталося або що зробили |
|---|---|
| Вчора 22:00 | Фактичний початок інциденту (зник інтернет) |
| Сьогодні 08:00 | Студентка залишила скаргу, створено тікет #54 |
| Сьогодні 18:50 | Проведено діагностику (MaksymGD), виявлено завислий комутатор |
| Сьогодні 19:00 | Апаратне перезавантаження комутатора, відновлення роботи мережі |

## Першопричина

Апаратне або програмне зависання комутатора, який обслуговує точки доступу на 4-му поверсі гуртожитку №3.

## Чому це не спіймали раніше

Система моніторингу не зафіксувала падіння вузла або не надіслала алерт черговим. Ми дізналися про інцидент виключно завдяки скарзі користувача через багато годин після падіння.

## Що спрацювало добре

Наявність резервного каналу зв'язку (мобільний інтернет у студентів), що дозволило їм подати заявку.

## Що спрацювало погано

Відсутність проактивного моніторингу мережевого обладнання в гуртожитках — це пряме порушення заявлених SLO (P2 вимагає реакції за 1 годину, а тут пройшла ніч).

## Чого ми навчилися

Без автоматичних алертів від комутаторів доступу на місцях ми повністю сліпі й не можемо гарантувати виконання SLA для кінцевих користувачів.
