# Постмортем: Компрометація трьох акаунтів викладачів та розсилка спаму (#17) — 2026-11-02


## Коротко

| | |
|---|---|
| Сервіс | 04 — Ідентичність (SSO / LDAP) |
| Пріоритет | S2 (Безпековий інцидент) |
| Тривалість | ~7 годин (нічний період до ранкового виявлення) |
| Кого зачепило | 3 облікові записи викладачів; потенційний ризик блокування поштового домену університету |
| Виявлено | Зверненням суміжної команди (адміністратор пошти, Команда 1) |

Протягом ночі з трьох скомпрометованих облікових записів викладачів було надіслано ~4 000 спам-листів на зовнішні адреси. Інцидент виявила Команда 1 та передала в Сервіс 04. Згідно з регламентом `docs/slo.md`, чергова зміна зберегла докази, ізолювала акаунти, перевірила масштаб і відновила доступ через MFA.

## Першопричина

1. Витік облікових даних (паролів) трьох викладачів через зовнішні фактори (фішинг або повторне використання паролів).
2. Відсутність обов'язкового багатофакторного захисту (MFA) для групи співробітників у каталозі SSO / LDAP.
3. Відсутність автоматичного ліміту на кількість вихідних листів на годину з одного акаунта.

## Чому це не спіймали раніше

* Моніторинг та служба Ідентичності не мали налаштованих алертів у реальному часі на нічні входи з нетипових IP-адрес для облікових записів викладачів.
* У системі не було превентивного блокування за підозрілою активністю (rate-limiting), тому розсилка зупинилась лише після втручання людини вранці.

## Що спрацювало добре

* Оперативна маршрутизація тікета суміжною командою.
* Дотримання процедури S2: чергова зміна не знищила докази поспішним перезавантаженням, а спершу зберегла логи.

## Що спрацювало погано

* Великий час виявлення (TTD) — нічна атака тривала кілька годин до ранкового дзвінка.
* Відсутність примусового MFA для всієї категорії співробітників.
